
好的，这是将我们讨论的所有需求（全盘基线、每日回顾、时间纵深、逻辑严谨性）整合后的Agent完整设计方案。

# 全球宏观风险传导监测Agent —— 完整设计方案


## 一、核心设计理念

| 设计原则 | 说明 |
|---|---|
| **长时记忆锚定** | 首次运行时生成全盘基线分析，作为后续所有判断的“原点” |
| **每日滚动回顾** | 每次分析必须基于昨日完整结论 + 今日增量信息，保证逻辑连续性 |
| **强制归因机制** | 每天必须回答“今日相对昨天发生了什么本质变化”，防止随波逐流 |
| **路径依赖追踪** | 记录每条因果链的激活/验证/证伪过程，形成“危机演化史” |
| **置信度管理** | 对每个判断标注置信度，新证据需达阈值才能修正核心假设 |

### 5.2 Step 2：接入“今日增量”（数据采集层输出）

```

### 5.3 Step 3：执行“差异归因分析”（核心模块）

**强制回答三个问题：**

| 问题 | 分析逻辑 |
|---|---|
| **① 今天相比昨天，数据上有什么变化？** | 对比指标增量：KOSPI跌5.2%，韩元破1550，VKOSPI再创新高 |
| **② 今天的事件，在昨天的预测范围内吗？** | 昨日预测“韩国央行可能干预”→实际是金融监督院审查杠杆ETF，方向一致但主体不同→部分符合预期 |
| **③ 这种变化是趋势反转还是噪音？** | KOSPI连续3天跌幅超3%（累计-15%），叠加保证金新高→**判断为趋势强化，非噪音** |

**输出：归因结论模板**

```
【差异归因报告】
· 数据变化：KOSPI今日-5.2%，较昨日的-3.1%加速下跌；韩元正式跌破1550阈值
· 昨日预测验证：昨日预测“韩国干预”→今日监管审查启动，方向正确但力度弱于预期
· 趋势判断：连续3日暴跌+保证金新高+监管仅审查未实质救市→**趋势恶化**
· 置信度调整：链2（韩国→半导体）概率从60%上调至75%
```

## 六、第三层：记忆存储（数据库设计）

### 6.1 数据结构

```

## 八、开发路线图

## 九、技术选型

| 层级 | 推荐技术 |
|---|---|
| 编程语言 | Python 3.10+ |
| 数据采集 | `yfinance`, `pandas_datareader`, 付费API（路透/Bloomberg） |
| 数据处理 | `pandas`, `numpy` |
| 传导逻辑引擎 | Python 规则引擎（`durable_rules` 或 `PyKnow`）+ 自定义状态机 |
| NLP新闻处理 | GPT API / Claude API（结构化事件提取 + 影响判断） |

| 报告生成 | Python + Markdown → PDF（`weasyprint` 或 `reportlab`） |
| 调度部署 | Docker + 云服务器 + `cron`/`Airflow`（每日定时运行） |


## 十、局限性与风险说明

| 局限 | 说明 |
|---|---|
| **黑天鹅无法预测** | 突发战争、恐怖袭击、自然灾害等不在模型覆盖范围 |
| **数据滞后** | 部分关键指标（如企业财报、季度GDP）有1-3个月延迟 |
| **传导时滞不确定** | “A导致B”的时间窗口从3天到3个月不等，模型难以精确计时 |
| **政策干预打断** | 央行救市、资本管制等行为可随时打断原有传导链 |
| **NLP精度依赖** | 新闻事件的冲击强度判断依赖大模型能力，需人工复核关键事件 |
| **历史回测≠未来验证** | 过往逻辑在未来可能因结构性变化而失效 |
